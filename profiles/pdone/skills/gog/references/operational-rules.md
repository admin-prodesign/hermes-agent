## Employee-lane Sheets writes (Mattermost/Telegram)

Keep MCP. Do **not** unblock employee-lane `terminal`/`gog`/`sheets_safe_ops.py` because the requester's Google email is in a Drive editor/owner group. That group match authorizes typed MCP writes only. Terminal stays blocked (`pd_one_sender_tool_gate`): the shell is unbounded and Gog still runs as `admin@prodesign-group.com`, not as the employee.

Employee (and any session where `terminal` is blocked) write path:

1. `mcp__pdone_safe_ops__pd_one_drive_acl_authorize` for the exact sender + file id.
2. `hermes_tool_search` / `tool_search` with queries such as `sheets batch update` and `sheets get range`.
3. `tool_describe` then `tool_call` using the **exact** catalog names (`mcp__pdone_safe_ops__pd_one_sheets_get_range`, `mcp__pdone_safe_ops__pd_one_sheets_batch_update`, and siblings).
4. Dry-run, then live with `confirm_live_write` and range readback.

Never `tool_describe(["pd_one_sheets_batch_update", …])` without the `mcp__pdone_safe_ops__` prefix. A short-name `not_found` is a lookup miss, not unavailable tools. Retry search. Do not claim Sheets API unavailable, do not browser-type into Google Sheets, and do not ticket Andy for a blocked terminal.

A shared-room `terminal` block is not a failed `gog` call and not a channel deny. `gog` never ran. Permissions follow the exact sender. Do not tell Andy the room has no Drive path, and do not send him to Admin as the only reader. `tool_search` for `pd_one_google_drive_search_files`, then call the exact catalog name. A guessed name that returns `not_found` is a lookup miss. If the catalog shows only the three native `pdone_safe_ops` tools, the session did not receive toolset `mcp-pdone_safe_ops`. The native name hides the MCP Drive/Sheets tools. From an Andy/admin session that already has terminal, add `mcp-pdone_safe_ops` beside the existing Mattermost toolsets with `hermes -p pdone config set`. Do not replace that list with one name. Then use the typed tool. Do not stop an admin task. From an employee session, do not run `hermes config set` and do not unblock terminal. Config changes are outside that sender's approval set, and the shell still runs as admin. Say the live Sheet or share was not read. Do not browser-type the Sheet, and do not treat the unread file as a negative business finding.

Admin sessions may still use `sheets_safe_ops.py` via `terminal` when MCP is not needed. Employee-lane must not inherit that path.

## Google Sheets/Docs naming and robust schema handling

- When a user provides a Google Sheets link for analysis and says it is shared to `admin@prodesign-group.com`, do **not** conclude the Sheet is unavailable just because an unauthenticated `/export?format=csv` request returns `401 Unauthorized` or the generic Hermes Google Workspace OAuth files are missing. First try the authenticated Pro-Design Gog path: extract spreadsheet ID and `gid`, run a bounded `gog auth status/list` check, then use `gog sheets metadata` / `gog sheets values` / Drive export with `--account admin@prodesign-group.com --no-input` as appropriate. Only ask for upload/link-sharing after the authenticated Gog read path is unavailable or fails with a verified permission/auth error.
- Company-related Google Sheets and Docs should use bilingual, company-prefixed titles like `良器-部門-表格中文名字 English Name`.
  - Pattern: `良器-` + department / owning function + `-` + Chinese file purpose + space + English purpose.
  - Existing/observed examples that match the family include `良器-資材-生管排程 Production Schedule`, `良器-模修課-模修 Mold Repair`, and `良器-模修課-模修-分析 Mold Repair Analysis`.
  - Older/project-only files may not match; use the convention for new company-maintained Sheets/Docs and when proposing renames.
  - For naming audits and rename proposals, read `references/company-sheet-naming.md`.
- For every Google Sheet PD One creates or manages, freeze row 1 when that row is the column header. A title-only first row is not a header; freeze the real header block instead, and say so. Keep pruning trailing blank rows and columns after writes. Map reads/writes by the live header row, not fixed column letters.
- **Create-time ACL + protection (Andy 2026-09-23).** Every new company Sheet: grant the matching department Google Group file-level `writer` (`type=group` readback). Tabs that are not meant for human UI edits get whole-tab protection with only admin identities as editors; department members still open via file Editor but must ask PD One to add/remove/pause rows. Do not raise the parent folder to writer just to match the file. Full procedure: `references/google-sheets-group-editor-and-admin-protection.md`.
- For reused Google Forms response workbooks and operator-grade survey analysis, read `references/google-forms-response-analysis-sheets.md`: use `linkedSheetId` from Forms raw output, do not assume `Form Responses 1`, filter by current survey cycle timestamp, match duplicated grid-question columns by exact header, and ignore `N/A`/blank values when averaging grades.
- Treat header names as the stable contract. It is okay for Andy to reorder columns later if header names remain unchanged; if headers are renamed/deleted, update the integration deliberately.
- Before appending or updating rows, read row 1 headers, build records by header name, then emit values in the sheet's current header order.
- For targeted updates, prefer resolving the row by stable identifiers (IDs/post IDs/record keys) and writing only the intended row/cells in current header order. Avoid whole-sheet rewrites that can overwrite manual review/status edits.
- For PD One `review_log` / audit-log reference IDs, use a stable `review_log_id` column and verify every existing and future row is populated; see `references/review-log-stable-ids.md`.
- After a user-facing column reorder, run a dry-run/no-op sync verification. If values shifted (for example channel names under timestamp fields or URLs outside the link column), patch the producer first, then repair/clear shifted rows and verify a second run appends nothing unexpected. See `references/sheets-column-reorder-sync-repair.md`.
- Business record sheets should not ingest PD One/Andy/admin approval chatter, image-only rows, or bot status dialogue unless those messages are explicitly part of the business source record; add skip logic and verify cleanup during repairs.
- For IML Loss Control / paper-loss Mattermost-to-Sheets workbooks, use `references/iml-loss-control-reply-analysis.md`: position `回覆原因分類` as reply-reason analysis (not final root-cause judgment), regenerate classifications after `原因分類參考` changes, avoid auto-adding official categories without owner confirmation, ignore Markdown `#####` as a paper-batch value, and hide internal sync IDs from daily-use views when possible.
- Facilities LINE work-report tracker parsing has a dedicated reference: `references/facilities-line-work-report-tracker-parsing.md`. Match equipment tokens such as `T1`/`T22` to `ERP_Data` → `ERP_Data_Combined[Type=Equipment]`, preserve raw LINE text, and mark media-only or multi-equipment reports for clarification/review instead of guessing.
- If formulas, filter views, protected ranges, or dashboards depend on specific column positions, document that exception clearly in the sheet/runbook and keep those ranges updated when columns move.
- Print orientation is not a `SheetProperties` field. A fields path `sheets.properties.pageSetup` is rejected. Do not send `updateSheetProperties` for `pageSetup.orientation`, and do not claim that call changed portrait or landscape. If the user asks for a portrait aspect ratio, measure live row and column pixel sizes, keep those row heights, and scale column widths so the used grid width:height matches 210:297. Report the measured ratio. Say the print-direction setting was not changed.
- A tab that has `protectedRanges` is not automatically a PD One write block. Colleagues editing in the Google UI does not prove or disprove the API path. Before asking humans to fill cells, read live spreadsheet metadata: if `requestingUserCanEdit` is true for the Gog account (`admin@prodesign-group.com`) or that account/group is in `editors.users` / `editors.groups`, run typed dry-run then live `sheets-batch-update` with exact-cell readback. Only report a protection block when the API returns a protection error, `requestingUserCanEdit` is false, or the editor list is empty and `requestingUserCanEdit` is absent. An empty editor list means the file writer cannot edit the cells and cannot add itself with `updateProtectedRange`. Do not try that call. Name the Drive owner and stop. Do not browser-type the cells, and do not rename a tab to imitate a cell change. Example: HDPE comparison tab `HDPE原料規格表比較` on workbook `1DavCvZ_ioxKIgDiLvkEy_wqrIsOO8gOm0c71eWnFNBs` is sheet-protected but lists `admin@prodesign-group.com` as an editor.

## gog under cron/systemd and isolated agent homes

- Cron, systemd, Hermes profiles, and OpenClaw/Codex agent sandboxes may run with a different `HOME` than the host user. When Gog reports missing OAuth credentials, first compare the active `HOME`, `GOG_HOME`, and `gog auth status --json --no-input` against the intended credential home; do not assume `/home/prodesign/.config/gogcli` is visible.
- Cron and unattended shells often have a minimal `PATH`; do not assume `gog` is discoverable there. Use an absolute path from `command -v gog` or export a safe path such as `/home/prodesign/.local/bin:/usr/local/bin:/usr/bin:/bin` in wrappers.
- Recurring jobs that call `gog` should log the resolved binary once (`command -v gog`) and fail loudly on missing credentials/binary instead of posting success summaries that were not actually verified.
- For PD One/Hermes isolated profile runs, a safe credential repair is usually to set an explicit `GOG_HOME` for that profile or import/copy the approved Gog config into the profile-owned config directory, then verify with `gog auth list --json --no-input` and a read-only Sheets/Drive smoke test. Treat this as credential/config work: require approved-user authorization before copying or importing tokens, avoid dumping token contents, and keep Gmail send blocked unless explicitly approved.
- For the exact PD One isolated-profile copy pattern — profile-local Gog config/keyring copy, OpenClaw keyring-password file, shared wrapper shim, no-Gmail verification, and pitfalls — read `references/pd-one-isolated-profile-gog-credentials.md`.
- When Andy/admin needs to approve expanded Gog OAuth scopes interactively, use the noVNC handoff pattern in `references/pd-one-gog-oauth-vnc-handoff.md`: generate a consent URL with operational Workspace services but no Gmail. Prefer the direct callback pattern when the user wants the auth to complete in-browser; see `references/google-groups-oauth-novnc-callback.md` for the host listener + container localhost proxy pattern and the `x11vnc` startup fix. Fall back to `--remote --step=1/2` only when copying the final redirect URL is acceptable. For Google Groups admin work, include `admin.directory.group`, `admin.directory.group.member`, and `apps.groups.settings` via `--extra-scopes`, and verify Gmail scopes remain absent.
- For Google Groups admin work (create groups, copy settings, add members/subgroups), read `references/google-groups-admin-oauth-and-safe-ops.md`: append `admin.directory.group`, `admin.directory.group.member`, and `apps.groups.settings` using `--extra-scopes`, prefer visible noVNC handoff when the user finds headless/remote auth troublesome, avoid pipe-to-interpreter/token-export workarounds, and verify group/settings/member readbacks before reporting success.

## Google Sheets reminder / notification automation verification

- When a user asks if a tracker is "wired" to send reminders, split the answer into (a) Sheet reminder-date/recipient fields and (b) verified automatic sending. Reminder formulas or `Reminder Date` columns do not prove sends happen.
- Verify automation by checking Sheet structure, Apps Script triggers/source, external cron/job/workflow records, and actual send/log receipts before saying reminders are active.
- For PD One no-agent reminder automations, prefer a script that reads live Sheet headers through the approved Gog wrapper, prints nothing on normal no-op ticks, prints one bilingual Mattermost-ready alert only when due rows exist, and keeps a state key such as `row_id|reminder_date` to prevent duplicate sends. Schedule via `cronjob(no_agent=True, deliver='origin' or approved channel)` and verify with both current-date no-op and future-date dry-run fixture.
- A note that says the master tab drives generated tabs is not proof. If the job reads only the generated tabs, or rebuilds them from a hardcoded list, say master edits do not sync. Wire refresh to read the live master, preserve cycle status, and skip invalid rows before claiming adds or owner changes flow through.
- A frequency plus cutoff means every occurrence in the named years, not the sample due date in an upload. Do not generate rows when cutoff, anchor month, and note disagree; ask for one day and a month from 1 to 12.
- Do not map a nickname or group label onto a department channel. Look up the exact channel or group first. Changing the reminder destination is a new external send, not an in-place sheet edit.
- For the full checklist and reporting pattern, read `references/sheets-reminder-automation-verification.md`.

## Google Sheets cell-note overlays

- Treat `gog sheets update-note` as a metadata write requiring the same approval discipline as values/formula writes.
- Read access does not prove note-write access. Before bulk note work, do a one-cell smoke write and immediate `gog sheets notes` readback after the file owner grants editor permission.
- Preserve human notes by appending/replacing only an automation-owned marked block such as `[PD One ...]`; do not blindly overwrite existing notes unless explicitly requested.
- For large note overlays, avoid a single long command/script. Generate note text files, write notes in small idempotent chunks, and recompute remaining work from current notes after each chunk. If a long run times out after partial success, continue with chunking rather than rerunning the identical long command.
- For recurring note overlays, make the job delta-based and API-efficient: read existing notes for only the target columns/range, compute the desired automation-owned blocks, and call `update-note` only for cells whose final note text changes. Do not rewrite all notes after every upstream refresh.
- Recurring note overlays should use a source freshness watermark (for example dashboard run ID or published last-refresh timestamp) and skip no-op runs when the upstream source has not changed. If a prior run only processed part of a chunk, recompute remaining changed cells from current notes rather than trusting stale local state.
- Verification for note overlays should include both metadata and value safety: count markers in the target columns, spot-check sample notes, and compare/read back visible values for the approved range so you can truthfully report that only notes were touched.
- Verify completion by reading note metadata for the target columns and counting the automation marker, then spot-check visible sheet values separately.

## Google Sheets append payload sizing

- When appending many rows via `gog sheets append --values-json`, do not pass a large full dataset as one command argument; it can hit OS argument-length limits before the API call is made.
- Chunk appends into small batches (for example 25–100 rows depending on cell text size), sum `updatedRows` / `updatedCells`, and make the sync idempotent with stable dedupe keys so partial reruns do not duplicate rows.
- Verify a recurring sync by rerunning once and confirming the second run is a no-op (`rows_ready=0`, or only genuinely new rows are appended).

## Bound Apps Script updates

- The menu runs the bound project (`Code.gs`), not a sheet cell that stores a copy of the source. Editing that cell, or proving the Sheet owner is `admin@`, does not change the running program. Say so when those two differ.
- From Mattermost, patch only through `mcp__pdone_safe_ops__apps_script_project_ops`. Call `list_registered_projects` first. If that live list omits the bound script id, stop. Do not fall through to `gog`, token export, or `projects.updateContent` in a shared room: a card-risk shell stays blocked there, and the tool refuses unregistered ids on purpose. Ordinary `gog` reads are allowed for Andy. An unregistered script id is still a stop.
- Do not relabel a script patch as a cell edit to force or suppress a PDAPP card. Writer on the Sheet is not a script-edit grant. Do not ask the requester to open Apps Script or to get code-edit rights.
- When an employee refuses to share a personal bound script, do not register that container and do not ask for Editor. A company-owned copy is a new spreadsheet and a new script id. This lane cannot clone an unregistered project. Hand the copy to Andy only after the employee names that source. Do not open a decision-only ticket before a named source exists. If that source is the live sheet behind a Portal page, do not request the copy until the employee separates a non-live company copy from an explicit cutover. A copy does not retarget the live page.
- Adding a script id to the allowlist file is not active until the MCP process that serves the tool reloads. Do not claim the patch path is open because the file changed.
- When shell is allowed (Admin channel or an unattended job) and `gog appscript` still has no update command, use `references/appscript-update-content.md`. Prefer the registered MCP tool when the project is already listed.
- Treat full Apps Script exports/update responses as secret-bearing working files if the script contains app API keys; verify by update time and hash, then delete temp token/payload/source snapshots instead of committing them.
- Sharing the spreadsheet as Editor lets a person open Extensions → Apps Script. It does not register the bound project, and it does not let this lane copy or patch `Code.gs`. Do not ask the requester to change Viewer to Editor for that. A pasted `Code.gs` text file is design evidence only; it does not change the menu.
- A Drive copy of a spreadsheet gets a new bound script id. The source `script.google.com/home/projects/<id>/edit` URL is not the copy's script id. Ask for the address bar of the copy's Apps Script editor, not the spreadsheet URL.
- Inspection-sync name gate: a model token is optional decimals, letters, optional `/` plus letters, then `-` plus digits. Keep `1LD/E-2` and `0.18LD-1`. A pattern that stops at `/E` and drops `-2` is too short. Do not drop a whole cell only because it fails `[digit][letter]-[digit]`. Drop a second name only when it has no model token and is a note (教育新人, 量達安排重工). A keyword include-list is not enough: new note sentences will appear, and a real name can contain those words. If the master list has no same-prefix row, print blank or 需核對 — do not substitute a near family. Same prefix still fails closed on 桶 versus 蓋, 含塞 versus 不含塞, and 平蓋 versus 軟蓋. Resin stays blank when the schedule has no exact row; residue such as a color or 含塞 prefix must not print as the resin. Log drops on the comparison tab. A keyword list in a pasted source cell is not proof the running script already does this.

## Office `.xlsm` files and Google Sheets repairs

- Drive-hosted Excel macro workbooks (`application/vnd.ms-excel.sheet.macroEnabled.12`) are not native Google Sheets, even when they preview in Drive; Google Sheets API and bound Apps Script repair work must target a native `application/vnd.google-apps.spreadsheet` copy.

## Multi-tab content checks and copied-file ACL

- `gog sheets export --format csv` exports only the first tab. For a keep-or-drop string check across a workbook, use `--format xlsx` and search `xl/sharedStrings.xml` plus sheet XML, or `gog sheets get` each tab. Absence in the first-tab CSV is not absence in the file.
- A Drive file copied into a folder inherits that folder's existing writers. Before you report a surprise writer as a new grant, read the destination folder permissions. If the same email and role are already on the folder, say the new file inherited that access. Do not delete that permission unless the approved scope says to.

## Google Sheets allocated dimensions — mandatory final gate

- Google Sheets allocated blank rows/columns count against spreadsheet size, unlike Excel. After schema changes, imports, cleanup, generated reports, dashboards, training trackers, Forms-derived analysis tabs, or any PD One-created/managed workbook, do not merely clear unused values.
- Treat trailing allocated blank rows/columns as a **completion blocker** for generated Google Sheets. Before telling the user a Sheet is complete, read each tab's used range, delete/shrink unnecessary trailing rows/columns, then verify with `gog sheets raw ...` metadata (`gridProperties.rowCount` / `columnCount`).
- The final user report for any created/repaired Sheet should include the grid-trim verification result. If the trim was intentionally skipped, state the explicit reason (for example protected/formula expansion range, intentional future-entry padding, table/filter limitation) and what allocated dimensions remain.
- Delete or shrink unnecessary trailing blank rows/columns using `gog sheets delete-dimension` where available or lower-level Sheets API `spreadsheets.batchUpdate` `deleteDimension` / grid resize, then read back metadata. Dry-run first for live work whenever practical; Andy/admin approval is still required for live grid edits.
- Standard PD One helper for channel Google Sheets work: `/home/prodesign/.hermes/profiles/pdone/scripts/sheets_trim_grid.py`. Use it after a dry-run when `gog sheets` cannot expose row/column deletion. Export a short-lived Gog token to a private temp dir, pass `/home/prodesign/.config/gogcli/credentials-prodesign-admin.json`, remove the token afterward, and never print token contents.
- Preserve intentional padding, frozen headers/columns, filter views, protected ranges, and formulas before deleting dimensions; if any of these require keeping extra allocated rows/columns, record the exception in the Sheet/runbook and final reply.
- Google Sheets rejects `deleteDimension` when it would delete **all non-frozen rows** (`Invalid requests[0].deleteDimension: ... not possible to delete all non-frozen rows`). For a header-only tab with row 1 frozen, keep at least two allocated rows (the frozen header plus one blank data row), then verify the resulting grid dimensions.
- To append rows at the current grid edge, set `insertDimension.inheritFromBefore` true. False rejects a start index equal to the grid size. Then set the new row heights explicitly. Inheriting from the row above copies that row's pixel size onto the new rows.
